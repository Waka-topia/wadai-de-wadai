# コーディング規約

書式と、機械で検査できる規約は、設定ファイルを正本にしています。この文書には書きません。

- 書式：[`.prettierrc.json`](../.prettierrc.json)（import の順番や、Vue テンプレートの属性の順番も整える）
- lint：[`eslint.config.js`](../eslint.config.js)

コードを変えたら、`npm run format` と `npm run lint` を実行してください。どちらも自動で直せるところは直します。直せないエラーが残ったら、手で直してから次に進んでください。CI も同じ 2 つを実行し、差分やエラーがあると失敗します。

この文書には、lint では検査できない規約だけを書きます。

## 層を守る

- Firestore と Auth へのアクセスは `src/services/` に書きます。画面や store から Firebase の SDK を呼ばないでください。理由は [アーキテクチャ](architecture.md#層の構成) を見てください。
- 権限の判定をクライアントだけで済ませないでください。画面で隠しても、Firestore には直接リクエストを送れます。守る必要があるデータは `firestore.rules` で守ります（[認証と権限](auth-and-roles.md)）。
- `src/utils/` には、副作用のない関数だけを置きます。Firestore や store に触る処理は services か composables に置きます。

## すでにある部品を使う

新しく作る前に、同じことをする部品がないか探してください。

| やりたいこと                                             | 使うもの                                              |
| -------------------------------------------------------- | ----------------------------------------------------- |
| フォームの送信（ローディング、入力チェック、通知、遷移） | `useFormSubmit`（`src/composables/useFormSubmit.js`） |
| 画面下の通知                                             | `useSnackbar`（シングルトン）                         |
| スマホでボトムシート、PC でダイアログを出す              | `BaseBottomSheet`                                     |
| 確認ダイアログ                                           | `BaseDialog`                                          |
| 読み込み中・空・エラーの表示                             | `LoadingState`、`EmptyState`、`ErrorState`            |
| 外部リンクを開く                                         | `src/utils/externalLink.js`                           |

見た目をそろえるため、既存の画面と違う作りにするときは、理由を PR に書いてください。

## Vue コンポーネント

- `<script setup>` で書きます。Options API は使いません（lint は警告にとどめていますが、新しいコードでは使いません）。
- ルートの `meta` で決められること（PC での幅、背景色、アクセス制御）は、画面の中で個別に実装せず `meta` を使います（[アーキテクチャ](architecture.md#ルーティングとレイアウト)）。

## export と関数の書き方

default export と名前付き export、関数宣言とアロー関数は、どちらも使えます（lint で禁止していません）。新しいファイルでは、周りのファイルの書き方に合わせてください。サービスは、名前付き export のアロー関数で書いているものが多数派です。

## コメントと JSDoc

- コメントは日本語で書きます。何をしているかではなく、**なぜそうしているか**を書いてください。コードを読めばわかることは書きません。
- export する関数には JSDoc を付けます。引数と戻り値の形がコードから読み取りにくいときに、特に役立ちます。
- 回避策や暫定対応には、何を避けるためか、いつ外せるかを書きます（例：`firestore.rules` の「暫定ルール」のコメント）。
- コメントアウトしたコードは残さず、削除してください。必要になったら git の履歴から戻せます。
