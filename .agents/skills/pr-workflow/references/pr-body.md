# PR の本文

`.github/pull_request_template.md` の見出しに沿って書きます。読み手はレビューする人と、あとで経緯を調べる人です。

| 見出し                 | 書くこと                                                                                               |
| ---------------------- | ------------------------------------------------------------------------------------------------------ |
| 対応した issue の URL  | `Closes #番号` と書くと、マージ時に issue が閉じる。issue がなければ「なし」                           |
| 対応内容               | 何が変わるかを、利用者や開発者から見た言葉で 1〜3 行                                                   |
| 対応方法               | どう直したかと、その理由。ほかの案を選ばなかった理由があれば書く                                       |
| 動作確認               | 実行したコマンド（format・lint・build の結果）と、画面で確かめたこと。画面の変更ならスクリーンショット |
| レビューしてほしい点   | 判断に迷ったところ、影響が広いところ                                                                   |
| このPRでは行わないこと | 関連するが別の PR に回すこと                                                                           |
| その他                 | 文書の更新の有無など                                                                                   |

## 注意

- 最終チェックリストは、実際に行ったものだけにチェックを付けます。
- 文書（`docs/`、`AGENTS.md`、skills）の更新が必要な変更なら、同じ PR で直したかを「その他」に書きます。
- エージェントが本文を書いたときは、最後に `🤖 Generated with [Claude Code](https://claude.com/claude-code)` などの署名を付けます。
- 本文は一時ファイルに書いて `--body-file` で渡します。シェルの引数に直接書くと、改行や記号が崩れることがあるためです。
