# ruleset とマージ

`main` と `prod` には ruleset `base` がかかっています。

| ルール                    | 内容                                           |
| ------------------------- | ---------------------------------------------- |
| PR 必須                   | 直接 push できない。承認が 1 件必要            |
| ステータスチェック必須    | GitHub Actions の `ci` が成功していること      |
| 削除禁止・force push 禁止 | ブランチを消したり、履歴を書き換えたりできない |

`revival/2025-04` には ruleset `revival`（削除禁止・force push 禁止）がかかっています。

admin（リポジトリの管理者）は、これらのルールを迂回できます。

## マージのしかた

- マージは人が行います。エージェントは `gh pr merge` を実行しないでください。
- 方式は merge commit です。マージ後、ブランチは自動で削除されます。
- 承認が付いていない PR を admin がマージするときは、人に次のコマンドを実行してもらってください。

  ```
  ! gh pr merge <番号> --merge --admin
  ```

## よくある止まり方

| 症状                                                          | 対応                                                                               |
| ------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| `push` が `GH013` などで拒否される                            | `main` に直接 push しようとしている。ブランチを切って PR にする                    |
| PR が「Required status check "ci" is expected」のまま進まない | `ci` は `main` か `prod` 向けの PR でだけ動く。base ブランチを確かめる             |
| CI の「Check for changes」で落ちる                            | 手元で `npm run format` と `npm run lint` を実行し、直されたファイルをコミットする |
| fork からの PR で CI が動かない                               | 外部の人の PR は、管理者が Actions の実行を承認するまで動かない                    |
