# デプロイ

デプロイは本番のユーザーにすぐ影響し、Firestore のルールは全ユーザーのデータの守りを左右します。そのため、**デプロイのコマンドを実行する前には、毎回、何をどこに出すかを人に示して承認を得てください。** 承認を待つ間に、次の手順へ進まないでください。

環境の事実（Firebase プロジェクト、URL、ブランチ、環境変数の名前、1Password の named pipe）は `docs/environments.md` が正本です。迷ったらそちらを読んでください。

`.env*` の中身は読まないでください（`cat .env.production` や、ビルドした JS からキーを探すことも含みます）。キーが会話の記録に残るためです。

## 1. 何をどこに出すかを決める

| 依頼                             | 対象                                                               | 読むもの                                  |
| -------------------------------- | ------------------------------------------------------------------ | ----------------------------------------- |
| dev で確認したい                 | Hosting → dev                                                      | この先の手順 2〜4                         |
| 本番に出したい、リリースしたい   | main → prod の PR → （ルールに差分があればルール）→ Hosting → 本番 | `references/prod-release.md` を最初に読む |
| ルールやインデックスを反映したい | Firestore → dev、そのあと本番                                      | `references/rules-deploy.md`              |

依頼がどれに当たるか曖昧なとき（「デプロイして」だけのとき）は、dev か本番かを人に聞いてください。本番を勝手に選ばないでください。

## 2. 出す前の確認

```bash
git status -sb          # 未コミットの変更がないこと。あれば、出してよいか人に聞く
git fetch origin
git log --oneline -1    # 出すコミットを人に示す
firebase use            # 今のプロジェクトを確認する（npm script が切り替えるが、ログインの確認も兼ねる）
```

- dev には `main`、本番には `prod` のコミットを出します。ブランチが違えば、切り替えてよいか人に聞いてください。
- `firebase use` がログインのエラーになったら、人に `! firebase login --reauth` を実行してもらってください。

## 3. デプロイする（承認を得てから）

| 対象           | コマンド              |
| -------------- | --------------------- |
| dev の Hosting | `npm run deploy:dev`  |
| 本番の Hosting | `npm run deploy:prod` |

どちらの script も、`firebase use` の切り替え → `.env.*` を読んでビルド → `firebase deploy --only hosting` を行います。ビルドで Firebase の設定が空になる、1Password のパイプが読めない、などのエラーが出たら `references/troubleshooting.md` を読んでください。

## 4. 出したあとの確認

```bash
bash .agents/skills/deploy/scripts/verify-deploy.sh dev    # 本番なら prod
```

このスクリプトは、トップページ・Service Worker・manifest・トップページが読み込む JS が 200 で返ること、そして配信されている JS のファイル名が手元の `dist/` と一致することを確かめます。キーや中身は表示しません。

最後に、人にブラウザで主な画面を開いてもらうよう頼んでください。PWA なので、古い版がキャッシュから表示されることがあります。そのときは再読み込みを 2 回してもらってください。

結果は、出したコミット、対象の環境、スクリプトの結果、人に確認してほしい画面、の順に報告してください。
